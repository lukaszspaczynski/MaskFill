# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
tools/build.sh [Debug|Release]   # build app + extension (ad-hoc signed)
tools/run.sh   [Debug|Release]   # build, then launch the app to register it with Safari
python3 tools/make-icons.py      # regenerate the placeholder icon set in src/images
```

There is no JavaScript toolchain — no npm, bundler, linter, or test runner. Files
in `src/` are copied verbatim into the extension bundle, so a syntax check is the
only static verification available:

```sh
node --check src/background.js
```

No test suite is configured.

## Architecture

Two layers that are built together but developed very differently:

- **`src/`** — the actual Manifest V3 web extension. Plain HTML/CSS/JS, no build step.
- **`xcode/PageInfo/`** — a macOS container app generated by
  `safari-web-extension-converter`. Safari can only install an extension that ships
  inside an app; the app itself does nothing but host it and show install instructions.
  `SafariWebExtensionHandler.swift` is the native message endpoint and is currently
  an unused stub.

The Xcode project references `src/` through **relative paths** (`../../../src/...`),
not copies. Editing `src/` and rebuilding is enough — never re-run the converter just
to pick up source changes.

`src/popup`, `src/options`, `src/shared` and `src/images` are Xcode *folder
references*: new files inside them are bundled automatically. A new file at the top
level of `src/` is not — it must be added to the extension target's Resources phase
(or the project regenerated).

### Everything is a classic script, not an ES module

Safari does not support module service workers, so `"type": "module"` was removed from
the manifest and nothing uses `import`/`export`. `src/shared/settings.js` is the single
copy of the settings logic and is loaded three different ways:

| Context            | Mechanism                                              |
| ------------------ | ------------------------------------------------------ |
| Content script     | listed before `content.js` in the manifest's `js` array |
| Service worker     | `importScripts("shared/settings.js")`                   |
| Popup / options    | plain `<script src>` before the page's own script       |

It exposes `globalThis.Settings`. Keep it dependency-free and side-effect-free so all
three loaders stay valid; if you reach for `import`, the service worker breaks silently.

### Message flow

The popup pulls, the content script pushes:

- Popup → `browser.tabs.sendMessage(tabId, {type:"getPageInfo", settings})` → content
  script replies with stats. A rejected promise means there is no content script in
  that tab (internal page, or host access not granted) — the popup treats it as a
  normal outcome, not an error.
- Content script → `{type:"reportPageInfo", stats}` → background, which sets the
  per-tab badge. Badge text is per-tab, so Safari clears it when the tab closes.

Message handlers must return a Promise to reply and `false` otherwise. Returning a
Promise for a message you do not handle will swallow other listeners' replies.

Settings live in `browser.storage.sync` and are seeded on `onInstalled`. The
`blockedHosts` list suppresses the content script's work entirely for matching hosts.

## Gotchas

**Safari forgets local extensions.** Develop → *Allow Unsigned Extensions* resets on
every Safari restart. If the extension vanishes from Safari Settings, that is why, not
a build problem.

**Bundle identifier case must match `--app-name`.** The converter derives the app id
from `--app-name` but uses the literal `--bundle-identifier` for the extension target,
so `--bundle-identifier com.example.pageinfo --app-name PageInfo` produces
`com.example.PageInfo` and `com.example.pageinfo.Extension` — which fails
`ValidateEmbeddedBinary` with "embedded binary's bundle identifier is not prefixed with
the parent app's". Keep the last component spelled exactly like the app name.

**The converter warns about unsupported manifest keys** and those warnings are worth
acting on rather than ignoring — `type` and `open_in_tab` were both removed for this
reason.

## Placeholders to replace before shipping

- Bundle identifier is `com.example.PageInfo` in `xcode/PageInfo/PageInfo.xcodeproj`.
- `src/images/*` are generated placeholders (a blue disc with an "i"). Replacing them
  means deleting `tools/make-icons.py`, which would otherwise overwrite real artwork.
- Builds are ad-hoc signed with no development team; distribution requires a real one.
- The manifest has no `default_locale` / `_locales`, so nothing is localized.

## Regenerating the Xcode project

Only needed when changing platforms, app name, or identifiers — it discards manual
project edits.

```sh
rm -rf xcode
xcrun safari-web-extension-converter src \
  --project-location xcode --app-name PageInfo \
  --bundle-identifier com.example.PageInfo \
  --macos-only --swift --no-open --no-prompt --force
```

The project is macOS-only. Adding iOS later is `--rebuild-project` rather than a
fresh conversion.
